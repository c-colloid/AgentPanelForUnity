# スクリプトの再コンパイル・Play モードとの共存

[操作ガイド](../USER-GUIDE.md) > スクリプトの再コンパイル・Play モードとの共存

- スクリプトを変更するとドメインリロードが起きますが、パネルは直前に CLI プロセスを終了してセッション ID を保存し、リロード後に同じセッションへ自動で再接続します(バナー「前回のセッションに再接続しています...」→「セッションを再開しました。」)。エディタを再起動しても同様に前回のセッションが復元されます。
- ターンの途中でリロードが起きた場合は、再接続のあとパネルが自動で「続行」を送り、エージェントが続きを実行します(既定の動作。会話ログに「自動継続」と明示されます)。自動継続を OFF にしている場合は「直前のターンはスクリプトの再読み込みにより中断されました。」のバナーが出て、「続行」を押すまで待ちます。

  ![中断バナーと「続行」ボタン](../images/guide/14-interrupted.png)
- この自動継続は 設定 > Unity 連携 > Unity操作(UapOps) の「中断後に自動継続する」(既定 ON)です。Play モードの出入りやスクリプト保存後のフォーカス復帰のたびに続きを送ります。中断のたびに自分で確認してから続けたい場合は OFF にしてください。回数の上限はありません。止まるのは、CLI プロセスが 4 回続けて終了して再接続が停止したとき(下記の「再接続」バナー)と、あなたが停止ボタンを押したときだけです。
- エージェントが C# を書いてコミットした後も、コンパイルの完了を待って自動で作業を続けます。同じ場所の「コンパイル後に自動継続する」(既定 ON)で、コンパイル結果を添えた継続ターンを送ります(会話ログに明示されます)。コンパイルのたびに止めて確認したい場合は OFF にしてください。継続ターンがさらにスクリプトをコミットした場合も、そのリロード後に再び継続するので、書く→コンパイル→エラーを直す のループを無人で回せます。回数の上限はなく、止まる条件は「中断後に自動継続する」と同じです(エージェントがコミットをやめたとき、再接続が停止したとき、停止ボタンを押したとき)。
- リロードのたびにターンが切れること自体を避けたい場合は、同じ場所の「スクリプトのリロード中もエージェントを動かし続ける(実験的)」を ON にします(既定は OFF、Claude Code のみ)。CLI を小さな補助プロセスの下で動かし、Unity がリロードしている間も止めません。リロード後は同じプロセスにつなぎ直すので、中断バナーも「続行」も出ず、ターンはそのまま続きます。切り替えは次回の接続から効きます。補助プロセスが使えない場合や、つなぎ直せなかった場合は、これまでどおり終了して再接続します。Unity が 25 秒以上戻らない間に呼ばれた Unity 操作ツールは「まだリロード中」のエラーを返します(実行はされておらず、エージェントが呼び直せます)。
- Play モード中に Unity 操作ツールがタイムアウトする場合は、Project Settings > Editor の "Enter Play Mode Settings" を見直してください(設定に「Project Settings > Editor を開く」ボタンがあります)。
- CLI プロセスが落ちると「エージェントのプロセスが終了しました。」のバナーとヘッダーの再接続ボタンが出ます。3 回までは自動で再接続し、4 回続けて落ちると自動再接続を止めて「再接続」を待ちます([困ったときは](troubleshooting.md))。
