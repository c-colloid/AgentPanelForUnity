# ベイクのマテリアル: 共有マテリアルをそのまま使う、シーンのインスタンスを触らない(2026-10-18)

対象: Agent Panel Pro の `uap_model_bake`(Model の書き出し)。報告 2 件への対応。

## 報告

1. **共有マテリアルを指定できない。** Model のルートに `materials`(スロットごとのマテリアル)を設定しても、ベイクはそれを
   「テンプレート」として毎回 `<name>[_slot].mat` を新しく作り、そちらを割り当てていた。「生成しない」「既存のものを使う」
   という選択肢がなかった。
2. **シーンのインスタンスに勝手に上書きが付く。** スロット数が増えたベイクは、焼いたメッシュを表示しているシーン内の
   すべてのレンダラーに自動生成マテリアルを後ろから足していた(結果の `renderersExtended`、2026-10-14 の
   `2026-10-14-exact-modeling-improvements.md`)。プレファブのインスタンスではこれがインスタンスの上書きになり、
   プレファブ側を正しく設定しても上書きが勝つ。ミキサーのシェイカーが知らないうちにグレーになった原因。

## 変更

### `materials` オプション(既定 `model`)

| 値 | スロットのマテリアル | 焼いたマップ(法線 / AO) |
|---|---|---|
| `model`(既定) | ルートの `materials[slot]` があればそれ**そのもの**(共有、変更しない)。無いスロットは生成 | PNG として書き出し、結果の `assets` に出す。共有マテリアルには割り当てず、警告でパスを示す。生成したスロットには従来どおり割り当て |
| `generate` | 全スロットを生成(`materials[slot]` はテンプレート)。これまでの既定 | 生成マテリアルに割り当て |
| `none` | 作らない・割り当てない | PNG のみ |

結果に `materials: {mode, sharedSlots}` を出す。`assets.material` は slot 0 のマテリアルのアセットパス(共有ならそのパス、
`none` なら省略)。共有マテリアルにマップを割り当てないのは、ユーザーの共有アセット(他のプロップも使う)を書き換えないため。
マップを載せた専用マテリアルが欲しい場合は `generate`。

### シーンの編集はベイク自身の `(baked)` オブジェクトだけ

- `ExtendRenderers`(シーン内のレンダラーに新スロットのマテリアルを足す)を廃止。代わりに `ShortRenderers` が「焼いたメッシュを
  サブメッシュ数より少ないマテリアルで表示しているレンダラー」を数えて `renderersShort` に出し、警告で名前(階層パスと
  「2 of 3」)を列挙する。編集はしない。
- `(baked)` オブジェクトも、ユーザーがプレファブのインスタンスにしているとき(`PrefabUtility.IsPartOfPrefabInstance`)は
  マテリアルを割り当てない(割り当てはインスタンスの上書きになる)。足りなければ上の警告に載る。インスタンスでなければ従来どおり
  割り当てる。

### 影響

- 既定が `model` になったので、ルートに `materials` を設定しているモデルは今日から共有マテリアルで焼かれ、法線マップは
  割り当てられない(警告で示す)。従来の挙動は `materials: "generate"`。
- `renderersExtended` は出なくなった(`renderersShort` に置き換え)。

## テスト

`Bake_Materials_UsesTheModelsOwnMaterialAsItIs_AndEditsNoSceneObjectButItsOwn`: 共有マテリアルが slot 0 にそのまま使われ、
`.mat` が生成されず、共有側に `_BumpMap` が付かず、警告がマップのパスを示す。メッシュを表示するマテリアル無しのオブジェクトは
`renderersShort` 1 と名前で報告され、編集されない。`generate` で `Mat.mat` が作られ `_BumpMap` が載る。`none` でアセットが
報告されず、置いたオブジェクトは前のままで。

## 版

Pro 0.14.0-beta.5(再カット)。
