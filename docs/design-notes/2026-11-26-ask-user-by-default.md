# 質問カードを ACP エージェントの既定の質問手段にする (2026-11-26)

`2026-11-25-acp-ask-user.md`(`uap_ask_user`)の 2e「エージェントへの案内」の改訂。

## 1. 背景

`uap_ask_user` を入れた時点の常設指示は控えめだった:

> ユーザーが決めることで**選択肢を挙げられるとき**は `uap_ask_user` で尋ねる。
> **自由回答の質問には使わない。**

この書き方だと「カードを使うかどうか」をエージェントが毎回判断することになり、少しでも
自由回答寄りだと思えば文章で質問してターンを終える。ユーザーから見ると、Claude Code では
質問がほぼ必ずカードで来るのに、Codex / Grok / Gemini CLI では来たり来なかったりする。

要望は「質問するときは質問パネルを使うのを既定の動作にしたい」。

## 2. 変更

常設指示(`AgentHub.ComposeAskUserSteeringSection`)の向きを逆にした。

| | 変更前 | 変更後 |
|---|---|---|
| 既定 | 文章(カードは条件を満たすときだけ) | カード(文章は例外) |
| 自由回答寄りの質問 | カードを使わない | ありそうな答えを 2〜4 個挙げてカードで出す |
| 文章で尋ねてよい場合 | 選択肢を挙げられないとき全般 | 候補を 1 つも挙げられないとき、またはツールが `unavailable` を返したとき |
| 既に言われたことの確認 | しない | しない(変更なし) |

自由回答寄りの質問をカードに載せてよい根拠は、カードが自動で足す「その他...」
(`2026-08-12-askuserquestion-other.md`)。候補が外れていてもユーザーはそこに書ける。
候補が並んでいる分、文章の質問より答えるのは速い。

ツールの説明文(`UapAskUserTool.Description`)も同じ向きに揃えた。常設指示は新規
セッションの最初のプロンプトにしか載らないが、ツールの説明はエージェントがツール一覧を
見るたびに読むので、会話が長くなったあとも効く側はこちら。

出す条件は変えていない: ACP 接続かつ UapOps の core モジュールが有効なときだけ。
Claude Code には足さない(組み込みの AskUserQuestion がある)。

## 3. 限界

- **強制ではない。** ACP にシステムプロンプトの枠は無く、指示は最初のプロンプトへの
  前置き。従うかどうかはエージェント次第で、長い会話では文章の質問に戻ることがある。
- **質問の回数は増やさない。** 変えたのは「尋ねるときの手段」で、「尋ねるかどうか」の
  基準ではない。確認の乱発を避けるため「既に言われたことは確認しない」は残した。
- 実エージェントでの通し確認は `2026-11-25-acp-ask-user.md` 4 節と同じく未実施。

## 4. 却下した代替案

- **設定にオン/オフを足す**: 文章で尋ねてほしい人向けの逃げ道になるが、設定項目と UI が
  1 つ増える。必要ならカスタム指示に 1 行書けば上書きできるので、今回は足さない。
- **毎ターンのプロンプトに短いリマインドを付ける**: 忘れにくくはなるが、毎ターン
  トークンを使い、会話ログ側で前置きを隠す処理も要る。まず文言の強化だけで様子を見る。
- **文章の質問をパネルが検出してカードに変換する**: 選択肢を機械的に切り出せる保証が無く、
  回答を次のユーザーメッセージとして送り直すことになる(`2026-11-25-acp-ask-user.md` 2a と
  同じ理由)。
